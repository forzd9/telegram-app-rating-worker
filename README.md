# بوت تقييم Telegram على Cloudflare Workers

هذا المستودع يحتوي على عامل Cloudflare Worker يستقبل تحديثات Telegram، ويعرض للمستخدم خيارات تقييم من نجمة إلى خمس نجوم، ثم يرسل التقييم ومعلومات مرتبطة بالمستخدم إلى جهة مالكة ثابتة في الشيفرة. هذا الوصف مبني على `worker.js` و`wrangler.toml` وسير عمل GitHub Actions؛ لم يُشغّل البرنامج أو يُنشر.

> **تنبيه قبل الاستخدام:** يحتوي `worker.js` على بيانات اعتماد ثابتة في المصدر. ينبغي اعتبارها مكشوفة، وإبطالها/تدويرها قبل أي استخدام، ثم تعديل التنفيذ لقراءة الاعتماد من سر Worker بدل تضمينه في الشيفرة. لا تنشر هذا المستودع قبل معالجة ذلك ومراجعة ما يُرسل إلى المالك.

## ما يفعله المصدر

- يرد على طلبات `GET` برسالة حالة نصية.
- يقبل طلبات `POST` على المسار `/webhook` ويعالج تحديثات Telegram بصيغة JSON.
- عند استلام رسالة يبدأ نصها بـ`/start`، يرسل رسالة ترحيب مع أزرار تقييم من 1 إلى 5 نجوم.
- عند اختيار تقييم صالح، يجيب عن استعلام الزر، ويزيل أزرار التقييم من الرسالة، ثم يرسل إلى المالك الثابت في الشيفرة رسالة تحتوي على التقييم ومعلومات المستخدم.
- بعد نجاح إرسال الإشعار إلى المالك، يرسل للمستخدم رسالة شكر. لا تظهر في المصدر قاعدة بيانات أو آلية لحفظ التقييمات.
- يرد بـ`404` على طلبات `POST` إلى مسارات أخرى، وبـ`500` عند تعذر معالجة الطلب.

## حدود التنفيذ

- لا يحدد المصدر طريقة تخزين التقييمات أو تصديرها أو حذفها؛ الإشعار المرسل إلى المالك هو السلوك الظاهر.
- هوية المالك ورمز Telegram مضمنان في المصدر بدل آلية إعداد آمنة. لا توجد حاليًا واجهة إعداد موثقة لتمرير رمز البوت كمتغير بيئة أو سر Worker.
- لا يوضح المستودع خطوات إنشاء البوت أو إعداد webhook لدى Telegram، ولا يحدد نطاقًا مخصصًا أو عنوان نشر بعينه. يجب إعداد webhook خارجيًا لعنوان العامل المنشور مع المسار `/webhook`.
- لا يظهر في الملفات تحديد للتحقق من مصدر طلب webhook، أو تحديد لمعدل الطلبات، أو منع تكرار التقييمات، أو إدارة موافقات واحتفاظ بالبيانات.
- `package.json` يذكر `index.js` كنقطة دخول بينما يحدد `wrangler.toml` الملف `worker.js`، كما أن `worker.js` يستخدم صيغة التصدير الافتراضية للوحدات. كذلك فإن أمر `test` في `package.json` مجرد عنصر نائب ينتهي بالفشل، وليس مجموعة اختبارات فعلية.

## المتطلبات والإعداد

الإعدادات الموثقة في الملفات هي:

- `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID`: اسما سرّي GitHub اللذان يتوقعهما سير النشر الآلي للوصول إلى Cloudflare. أضفهما في إعدادات أسرار المستودع دون وضع قيمهما في الشيفرة أو README.
- Node.js 22: الإصدار الذي يحدده سير عمل النشر في GitHub Actions.
- حساب Cloudflare مُعدّ لنشر Workers، وبوت Telegram مُعدّ على Telegram. لا توجد في المستودع خطوات إنشاء الحساب أو البوت.

**لا توجد قيمة `BOT_TOKEN` أو قيمة أخرى لرمز Telegram ينبغي إدخالها وفق إعداد حالي:** النسخة الموجودة من الشيفرة تضمّن الرمز داخل `worker.js` ولا تقرأه من إعداد بيئي. أزل هذا الاعتماد ودوّره، ثم أضف دعمًا صريحًا لسر Worker قبل نشر نسخة آمنة؛ مجرد إنشاء سر باسم ما لن يغيّر سلوك الشيفرة الحالية.

## النشر الموصوف في المستودع

ملف `.github/workflows/deploy.yml` يعرّف سير عمل ينشر عند دفع تغييرات إلى الفرع `main`، كما يمكن تشغيله يدويًا من GitHub Actions. يستخدم Node.js 22 ثم يستدعي `npx wrangler@latest deploy`، مع تمرير `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` من أسرار GitHub Actions.

يتطلب ذلك إضافة السرّين المذكورين إلى إعدادات المستودع، والتحقق من صلاحيات رمز Cloudflare وحسابه. بعد النشر، يلزم إعداد Telegram لإرسال webhook إلى عنوان العامل المنشور مضافًا إليه `/webhook`. لا يتضمن المستودع أداة إعداد webhook أو تعليمات مؤكدة لاستخراج عنوان العامل؛ استعن بإعدادات Cloudflare وTelegram الرسمية، ولا تضع رمز البوت في سجل أو عنوان URL عام.

هذه الخطوات تلخيص للملفات فقط، **وليست مجرّبة**. لا توجد خطوات بناء مستقلة أو اعتماديات تطبيق معلنة في `package.json`، ولا ينبغي اعتبار نجاح سير النشر دليلًا على سلامة تكامل Telegram أو جاهزيته.

## الخصوصية والأمان

عند التقييم، يبني العامل رسالة للمالك تتضمن التقييم، والاسم المعروض، واسم المستخدم إن وجد، ومعرّف Telegram، ورمز اللغة، وحالة Premium، ومعرّف المحادثة، ووقت التقييم. لذلك ينبغي إبلاغ المستخدمين بهذا الجمع والإرسال، والتحقق من الأساس القانوني والموافقة، وحصر الوصول إلى صندوق Telegram الخاص بالمالك، وتحديد مدة الاحتفاظ والحذف. لا توجد سياسة خصوصية أو آلية احتفاظ موثقة في المستودع.

قبل النشر:

1. ألغِ/دوّر رمز Telegram الثابت الذي سبق تضمينه في المصدر، ولا تعِد استخدامه.
2. انقل الرمز ومعرّف المالك إلى إعدادات سرية مناسبة، وعدّل الشيفرة لتقرأها من bindings آمنة بدل الثوابت؛ لا توجد هذه الآلية في النسخة الحالية.
3. لا تسجل الرموز أو بيانات المستخدمين، وقلّل البيانات المُرسلة إلى الحد اللازم، وأضف تحققًا مناسبًا من webhook وضوابط لمعدل الطلبات والتكرار.
4. راجع أذونات Cloudflare وGitHub Actions، وراجع سياسة الخصوصية والاحتفاظ قبل إتاحة البوت للجمهور.
